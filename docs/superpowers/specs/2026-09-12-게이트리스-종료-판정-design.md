## 0. 한 줄

**루프 한계는 종료 트리거이지 사유가 아니다** 를 게이트 **밖**에도 적용한다. 게이트를
안 거치고 끝나는 두 경로가 지금은 증거 상태를 보지 않고 무조건 `inconclusive` 를 찍는다.

## 1. 결함 — 원칙의 절반이 안 닫혀 있다

`018812d` 가 닫은 것은 **게이트를 타는** 종료다. 게이트를 안 타는 경로가 둘 남아 있다
(`graph/build.py`):

| 입구 | 조건 | 언제 |
|---|---|---|
| `_after_tools` | `loop_count >= MAX_LOOPS` 인데 `finalize_accepted` 가 없다 | LLM 이 마지막 회차에 finalize 말고 다른 도구를 불렀다 |
| `_after_analyze` | tool call 없이 텍스트만 응답 | 이탈 케이스 (loop 1 에도 일어난다) |

둘 다 `report_node` 백스톱으로 떨어진다. 거기서 `finalize_status` 가 비어 있으면
(반려는 이 필드를 안 찍으므로 이 경로에서는 **항상** 비어 있다) 무조건 `inconclusive`
다. 그래서 4축을 다 돌고 아무것도 안 갈린 분석과, 예산이 모자라 못 끝낸 분석이 **같은
사유**로 나간다 — 엔지니어가 받는 조치가 다른데("표본을 늘려라" vs "재실행하라")
하나로 뭉개진다. `018812d` 가 없앤 것과 **같은 결함**이고, 다만 원인이 제출 형태가
아니라 **사슬을 안 타는 것**이다.

**프롬프트로는 못 막는다.** 이 경로는 LLM 협조와 무관하게 코드 라우팅이 만든다.

### 지금 코드가 `inconclusive` 를 고른 근거 (반박)

백스톱 주석은 이렇게 적고 있다: *"사유는 그래도 inconclusive 다 — 이 근거는 게이트가
승인한 것이 아니다. 판별선을 넘은 통과 후보든 그 아래 잔차든, 지목·승인 절차를 거친
적이 없다."*

이 근거는 **승인**에는 맞고 **관측**에는 안 맞다. `no_signal`("타깃만 거친 후보가
없다")·`no_separation`("봤는데 안 갈렸다")·`no_comparable_data`·`tool_failure` 는
승인이 아니라 **도구 실행 결과에 대한 관측**이다. 게이트에서도 이 사유들은 지목을
요구하지 않고 오히려 `not claim_id` 를 하한으로 건다. 경로 B 는 제출 자체가 없으니
그 하한을 자동으로 만족한다.

## 2. 결정

- **관측 사유는 허용한다.** 증거 상태가 말하는 대로 낸다.
- **승인(`confirmed`)은 게이트 밖에서 안 나온다.** 금지 규칙을 따로 적지 않는다 —
  `(1)` 이 지목한 claim 을 요구하는데 경로 B 는 `claim_id` 가 비어 있어 **구조적으로
  불가능**하다.
- **새 판정 이름을 만들지 않는다.** 어휘가 늘면 게이트·목·운영 프롬프트 세 곳이 같이
  움직인다(이 저장소가 앞서 같은 이유로 새 이름을 안 만들기로 한 전례를 따른다).
- **게이트를 안 거쳤다는 사실은 판정문에만 남긴다.** 상태 키를 늘리지 않는다. 그 사실이
  필요한 것은 엔지니어가 아니라 **이 시스템을 고치는 사람**이다(프롬프트나 스크립트가
  종료를 제안하지 않았다는 신호).

## 3. 구조 — 백스톱이 사슬을 빈손 제출로 부른다

검토한 대안 셋 중 A 를 고른다.

| 안 | 내용 | 판정 |
|---|---|---|
| **A** | 백스톱이 `_finalize_gate` 를 빈손 제출·`loop=MAX_LOOPS` 로 부른다 | **채택** |
| B | 판정 사슬을 순수 함수로 추출해 두 소비자가 공유 | 구조적으로 더 옳으나 지금은 아니다 |
| C | 백스톱이 상태 술어를 다시 본다 | 규칙이 두 자리가 된다 — 이 저장소가 여덟 번 당한 유형 |

**B 를 미루는 이유**: 380줄 함수를 가르는 수술이고 `update[...]` 쓰기가 분기마다
섞여 있다. 그리고 실측상 **이 함수를 흔들 때마다 결함이 새로 났다**(직전 세 라운드).
사슬을 손댈 이유가 따로 생겼을 때 함께 한다.

**A 의 약점과 대응**: 제출이 없는데 제출인 척한다(호출부에 근거를 적는다). `(5) 반려`
가 안 열리는 근거가 `loop` 강제 하나에 달려 있다(훼손으로 잠근다).

### 동작

1. `finalize_status` 가 비어 있을 때만 탄다(조기 출구는 이미 찍고 오므로 안 걸린다).
2. `_finalize_gate({"claim_id": "", "hypothesis": "", "confidence": 0.0},
   loop=ya_config.MAX_LOOPS, scratch, findings)` 를 부른다.
   **`loop` 강제가 `(5)` 를 닫는다** — 텍스트 응답 이탈은 loop 1 에도 일어나므로,
   이게 없으면 종료 노드가 "반려" 문구를 내보낸다.
3. 임시 dict 에서 **`finalize_status`·`final_claims`·판정문 셋만** 꺼낸다.
   - `finalize_accepted` 는 안 옮긴다 — 상태에 거짓을 남긴다(읽는 곳인 `build.py`
     라우팅과 `tools_node` 는 이미 다 지나왔다).
   - `final_hypothesis` 도 안 옮긴다 — 제출이 없었으니 비어 있는 것이 사실이다.
   - `coverage` 도 안 옮긴다 — 백스톱이 같은 `findings` 로 이미 다시 세고 있고, 그
     자리에 "state 를 안 믿는다" 는 근거가 있다. 같은 값을 두 경로로 들이면 나중에
     한쪽만 바뀐다.
4. 판정문 뒤에 **"LLM 이 종료를 제안하지 않아 코드가 증거 상태로 판정했다"** 를 붙인다.
5. 그 판정문을 **`sent_findings` 사본에** 합성 finalize 레코드로 얹는다:
   `{"loop": state.get("loop_count", 0), "tool": "finalize", "args": {},
     "result": <판정문>, "thought": ""}`
   — `tools_node` 가 만드는 레코드와 같은 계약이라 목이 `[분석 과정]` 의 `- 게이트:`
   줄로 렌더링하고 운영 프롬프트가 그대로 인용한다.
   **상태의 `findings` 는 건드리지 않는다** — `superseded` 표시를 사본에만 붙이는
   선례와 같다. 감사 기록은 실제로 일어난 호출의 기록이고, 코드가 만든 판정은 그것과
   구분돼야 한다.

### 불변식

- **절대 후퇴하지 않는다.** `(4)` 가 여전히 바닥이다 — 관측 분기가 하나도 안 걸리면
  오늘과 똑같이 `inconclusive` 다. 이 변경은 사유를 **좁히기만** 한다.
- **버린 지목 괄호가 붙을 일이 없다.** `claim_id` 가 빈손이라
  `_drop_unapprovable_pick` 이 `None` 을 돌려준다 — 버릴 제출이 없다.
- **근거 목록은 오늘과 같다.** 지금 백스톱의 `_evidence_groups(bundle,
  bundle.ranked_groups())` 와 사슬 안의 호출이 같다. 지목이 없으니 `picked` 도
  `None` 이라 `←서술 기준` 이 안 붙는 것도 같다.

## 4. 곁가지 — 폴백의 거짓 포인터 (별건이지만 같은 함수다)

`report_node` 의 리포트 생성 실패 폴백이 `[결론]` 에 *"사유는 위 [판정] 줄"* 이라고
적는데, `[판정]` 줄은 **상태 이름만** 찍는다(`[판정] inconclusive`). 사유가 적힌
산문은 `findings` 의 finalize 레코드에 있다. `e17f223` 이 넣고 3차 리뷰가 놓쳤다.
같은 함수를 건드리는 김에 사유가 실제로 있는 곳을 가리키게 고치고 단언을 단다.

## 5. 검증

**표 하나로 경로 B 의 사유 여섯을 전부 돈다**(자리를 세어서 — 이 저장소가 여덟 번
당한 유형이다). 입구가 둘이므로 둘 다 같은 결과가 나오는지도 건다.

| findings | 기대 |
|---|---|
| 전축 침묵 | `no_signal` |
| `ALL_WEAK` | `no_separation` |
| 잔차 있음(아랫선 초과) | `weak_signal` |
| 전축 `no_paired_stratum` | `no_comparable_data` |
| 전축 실패 | `tool_failure` |
| 비어 있음 | `inconclusive` |

**훼손 여섯**:
1. `loop=MAX_LOOPS` 강제 제거 → 종료 노드가 반려 문구를 낸다
2. 합성 레코드를 사본이 아니라 상태의 `findings` 에 붙임 → 감사 기록 오염
3. "코드가 판정했다" 문구 제거 → 게이트 판정과 구분이 사라진다
4. `finalize_accepted`/`final_hypothesis` 를 상태로 옮김
5. 조기 출구 가드(`if not verdict`) 제거 → `no_anomaly` 가 덮인다
6. 사슬 호출을 빼고 `inconclusive` 로 되돌림 → 표의 여섯 자리가 빨개진다
