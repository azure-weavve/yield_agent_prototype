## 1. 문제 - 두 증상, 한 원인

C -> A -> B 로 이어온 일의 목적은 **"약한 신호와 무신호가 같은 출력이 되는 것"** 을
없애는 것이었다. 두 자리가 남았고, 둘 다 `graph/nodes.py:378` 한 줄에서 온다.

```
groups = bundle.ranked_groups()      # 통과 후보만
```

`(2a)` 만 `bundle.ranked_groups(bundle.passing() + residuals)` 로 합집합을 넘기고
나머지 판정은 위 `groups` 를 그대로 쓴다.

### 증상 1 - 잔차가 두 경로에서 소각된다 (실측 재현)

| 경로 | 자리 | 실측 |
|---|---|---|
| A. (4) 루프 한계 | `nodes.py:547` | 잔차 2건 · loop=7 · 환각 지목 -> `inconclusive` · `final_claims=0` |
| B. 게이트 미경유 백스톱 | `nodes.py:847` | LLM 이 finalize 를 아예 안 부르면 같은 이유로 잔차가 안 실린다 |

도달 조건이 다르다. 빈손 제출이면 `(2a)` 가 `(4)` 보다 앞이라 먼저 받으므로 **경로 A 는
환각·대체 이름을 되풀이 지목할 때만** 열린다. **경로 B 는 게이트 협조와 무관해
프롬프트로는 못 막는다.**

### 증상 2 - M4: 전축을 다 봤는데 아무것도 안 갈리면 출구가 루프 한계뿐 (실측 재현)

```
전축 4개 status ok · 통과 후보 0 · 잔차도 0 (score 0.10 < RESIDUAL_MIN_SCORE 0.25)
  loop=2 -> 반려  loop=7 -> inconclusive · final_claims=0
```

`(2) no_signal` 은 `"no_signal" in statuses` 를 요구하는데 이 상태의 status 는 전부
`ok` 다(후보는 났고 계산도 됐다. 다만 전부 약하다). `(3)`·`(3b)` 도 안 걸린다.
**"봤는데 아무것도 안 갈렸다" 를 말하는 판정이 없어**, 엔지니어는 실제로 일어난 일과
다른 사유("미확정 - 루프 한계 도달")를 본다. 2026-08-24 에 별건 M4 로 적힌 것이다.

## 2. 확정된 결정 (사용자 승인, 2026-09-09)

1. **`_fold_key` 는 안 고친다.** 대신 **조건부 합집합** - 지목 가능한 통과 후보가
   없을 때만 잔차를 더한다.
2. M4 판정 **신설**. 하한은 **전축 + 정직한 제출**.
3. M4 위치는 **`(2)` 앞**(= `(2a)` 바로 뒤). 하한 하나 추가: **비센서 후보가 실제로 났다.**
4. M4 문구는 **수치 + 대조·관측축** 을 말한다.
5. **대체(superseded) claim 의 반려는 설계된 동작**이다. 코드 변경 없음(§8).

## 3. 왜 `_fold_key` 를 안 고쳐도 되는가

B 설계 §14 는 "(4)에 합집합을 넘기면 통과 claim 과 잔차가 한 묶음에 섞이므로
`_fold_key` 에 `passes` 를 반영하라" 고 적었다. 그런데 B 설계 §10 은 이미
**"지목 가능한 통과 후보가 있을 때는 잔차를 안 싣는다"** 를 확정 계약으로 두었다.

두 문장을 겹쳐 읽으면 답이 나온다. **(4)와 백스톱에서도 그 계약을 그대로 지키면
섞임이 애초에 일어나지 않는다.** `_fold_key` 가 지금 안전한 이유(`(2a)` 하한 덕에
합집합의 비센서 claim 이 전부 미통과이고, 센서는 wafer 목록이 없어 항상
`__unfoldable__` 로 홀로 선다)가 네 자리(`(2a)`·`(2b)`·`(4)`·백스톱) 모두에서
똑같이 성립한다.

C 브랜치가 확정한 접기 계약을 건드리지 않는 것이 이 선택의 값이다. 건드렸다면
순위·교락·포함관계 테스트가 함께 움직이고, `group_to_dict::folded` 에 `passes` 키가
없어 묶음 전체가 `[잔차]` 로 찍히는 문제까지 같이 풀어야 했다.

**대신 포기하는 것을 명시한다**: "통과 후보는 있는데 확정을 못 하고 루프 한계로 끝난"
상태에서는 잔차가 여전히 안 실린다. 그것은 §10 의 확정 계약("강한 근거 옆에 약한 것이
나란히 서면 같은 무게로 읽힌다")이 그대로 적용되는 자리이지 누락이 아니다.

## 4. 게이트 - 합집합을 한 곳에서 정한다

네 자리(`(2a)` · `(2b)` · `(4)` · 백스톱)가 같은 규칙을 쓴다. 규칙을 네 번 적으면
이 저장소가 반복해 겪은 **"N 자리 중 N-1 자리만 고침"** 이 그대로 재현된다.
(`(2b)` 는 Task 4 가 M4 판정으로 추가한 네 번째 호출부다.)

```python
def _evidence_groups(bundle, passing_groups: list) -> list:
    """근거로 실을 묶음. **지목 가능한 통과 후보가 없을 때만 잔차를 더한다.**

    이 하한이 곧 접기 계약의 전제다 - 합집합의 비센서 claim 이 전부 미통과라야
    `_fold_key` 가 통과 claim 과 잔차를 한 묶음에 섞지 않는다(B §4 · C 계약).
    하한을 지우면 p 가 작은 잔차가 lead 를 뺏어 통과 근거가 `passes` 키도 없는
    `confounded_with` 로 강등되고 묶음 전체가 `[잔차]` 로 찍힌다.

    **잔차를 안 더할 때는 받은 목록을 그대로 돌려준다.** `ranked_groups()` 는
    호출마다 새 `ClaimGroup` 을 만들어(`find_group` docstring 의 경고), 다시
    만들면 호출부의 `picked` 와 `is` 비교가 항상 거짓이 되어 아무 claim 에도
    `picked_by_llm` 이 안 붙는다. 그래서 이미 만든 목록을 인자로 받는다.
    """
    residuals = bundle.residuals()
    if bundle.statistical_passing() or not residuals:
        return passing_groups
    return bundle.ranked_groups(bundle.passing() + residuals)
```

호출부는 `carried = _evidence_groups(bundle, groups)` 로 받고, **`carried is groups`
일 때만 `picked` 를 함께 넘긴다.** 잔차를 실은 목록에서 지목할 수 있는 것은 센서나
잔차뿐이라, `(2a)` 와 같은 이유로 그것을 서술의 축으로 삼으면 안 된다.

- `(2a)` 를 이 헬퍼로 바꿔도 **동작이 같다** - 그 분기의 하한이 곧 헬퍼의 조건이다.
- `(4)` · 백스톱 · M4(§5.4)가 이것을 쓴다.
- `(1)`·`(2)`·`(3)`·`(3b)` 는 그대로 `groups` 를 쓴다. `(1)` 은 통과 후보가 있는
  경로라 헬퍼를 써도 결과가 같지만, **`picked` 와 짝이 맞는 목록이어야 하므로**
  `groups`(= `find_group`·`layer_ranks` 가 쓴 바로 그 목록)를 그대로 둔다.

## 5. M4 - `no_separation`

### 5.1 조건

```python
# (2b) 갈리는 항목 없음 - 전축을 대조했는데 후보가 전부 아랫선 미만이다.
if (not unrun and not failed
        and not bundle.statistical_passing()
        and not residuals
        and any(c.kind != "sensor" for c in bundle.claims.values())
        and (not claim_id or claim is not None)):
```

각 하한의 이유:

| 하한 | 이유 |
|---|---|
| `not unrun and not failed` | `(3)` 과 같은 성격이다. "더 볼 것이 없었다" 는 **주장**이라 전축을 봐야 참이다. 부분 커버리지로 열면 근거 0건짜리 리포트로 조기 종료해, 있을지 모를 신호를 스스로 달아난다. |
| `not statistical_passing()` | 지목할 통과 후보가 있으면 이 판정은 거짓이다. |
| `not residuals` | 잔차가 있으면 `(2a) weak_signal` 이 더 정확하다(그쪽이 앞이라 실제로 먼저 받는다). |
| `any(kind != "sensor")` | **후보가 하나도 안 난 상태(전축 no_signal)는 M4 가 아니라 `(2)`다.** `status: "ok" if candidates else "no_signal"`(`tools/commonality.py:752`)이라 이 하한은 "1단 후보가 실제로 났다" 와 같은 뜻이고, 판정문의 최고 점수를 쓸 수 있다는 보장도 된다. |
| `not claim_id or claim is not None` | `(2a)` 와 같은 "정직한 제출". 약한 후보를 지목했다고 문을 닫으면 반려를 되풀이하다 루프 한계로 빠져 **이번에 고치는 결함이 그대로 재발**한다. 환각만 반려한다. |

### 5.2 위치 - `(2a)` 바로 뒤, `(2)` 앞

`(3)` 은 status 가 전부 `NO_DATA_STATUSES` 일 때만 열리므로 M4 와 **배타적**이다
(M4 는 `ok` 인 축을 요구한다). 그 앞뒤는 아무 효과가 없다.

**`(2)` 와는 실제로 겹친다.** 한 축은 `no_signal`, 다른 축은 `ok` + 약한 후보인 상태에서
둘 다 참이다. `(2)` 뒤에 두면 **빈손 제출은 `no_signal`, 지목한 제출은 `no_separation`**
으로 같은 증거가 제출 형태에 따라 다른 판정을 받는다. `(2a)` 를 `(2)` 앞에 둔 것과 같은
원칙 - **정보가 더 많고 조건이 더 좁은 쪽이 이긴다.**

### 5.3 판정문

```
갈리는 항목 없음 (전축 4/4 대조): 타깃과 대조군을 가르는 항목이 없다.
최고 분리 점수 0.10 으로 잔차 아랫선(0.25)에도 미달한다. 분석이 안 돌은 것도
근거가 약한 것도 아니라 lot 내부 대조로는 갈리지 않는다는 뜻이다.
lot 밖 대조군 또는 다른 관측축이 필요하다. 리포팅으로 진행한다.
```

최고 점수는 **비센서 claim 에서만** 뽑는다(센서는 자기 판별선을 쓰는 다른 눈금이라
같은 줄에 놓으면 "더 센데 졌다" 로 읽힌다 - `_gate_rejection` 이 이미 겪은 함정).
커버리지 문구는 기존 `_coverage_phrase` 를 쓴다.

### 5.4 실리는 근거

`_record_evidence(update, _evidence_groups(bundle), None)`. 정의상 통과 후보도 잔차도
없으므로 목록은 **비거나 통과 센서만** 남는다. `no_signal` 과 같은 이유로 센서는 실린다
(A 가 가른 `passing()` / `statistical_passing()` 이 여기서도 그대로다).
`picked` 는 안 넘긴다 - `(2a)` 와 같은 이유로, 지목이 있어도 **원인으로 확정하지
않기로** 했으므로 `picked_by_llm` 을 붙이면 리포트가 그 후보를 서술의 축으로 삼는다.

## 6. (4) 판정문 - 잔차를 싣고도 참이어야 한다

지금 문구는 `"미확정 (루프 한계 도달): 확정 근거 없이 리포팅으로 진행한다."` 다.
잔차를 실은 뒤에는 **거짓**이다. 잔차를 실었을 때만 뒷문장을 바꾼다.

```
미확정 (루프 한계 도달): 판별선을 넘은 후보를 확정하지 못했다.
아랫선을 넘은 잔차 N건을 근거로 싣는다.
```

**[Task 7 갱신 - 두 가지 이유로 위는 낡았다.** ① 이 §6 은 **2갈래**로 적혀 있는데
코드는 **3갈래**다(Task 6 리뷰 I-2 가 상한 절단에서 위 문구의 `N` 이 절단 전
`len(residuals)` 라 거짓이 될 수 있음을 잡았다). 지금 코드(`_finalize_gate` (4))는:

```
if carried is not groups:      # 잔차가 더해졌다(통과 후보가 없다)
    "... 아랫선을 넘은 잔차 {실제로 실린 residual_note}"
elif carried:                  # 잔차 없이 통과 근거(예: 통과한 2단 센서)만 실렸다
    "... 판별선을 넘은 근거 {len(carried)}건을 싣되 무엇이 원인인지는 확정하지 못했다."
else:                          # 근거가 정말 없다
    "확정 근거 없이 리포팅으로 진행한다."
```

② `residual_note` 는 절단 전 `len(residuals)` 가 아니라 `_residual_evidence_note`
가 실제로 실린 수(상한이 통과 근거로 다 차면 0건일 수 있다)를 센다.]**

## 8. 대체(superseded) claim - 설계된 동작으로 확정

`bundle.claims` 가 폐기 후보를 안 담으므로 `claim is not None` 하한은 환각뿐 아니라
**M3 로 대체된 앞 실행의 후보도** 거른다. 조사 §2.4 가 "미판정" 으로 남긴 자리다.

**판정: 고치지 않는다.** 반려 문구가 "대체된 앞 실행의 후보다" 라고 정확히 답하고
`_no_candidate_action` 이 물러설 길을 안내하므로, 그 반려는 결함이 아니라 **LLM 이
낡은 문맥(앞 실행의 ToolMessage)을 들고 있다는 사실을 알려 주는 자리**다. `(2a)` 로
조용히 삼키면 LLM 은 그 사실을 모른 채 끝나고 다음 분석에서 같은 이름을 다시 든다.
손해는 왕복 1회이며, **§4 가 `(4)` 에 잔차를 실은 뒤로는 최악의 경우에도 증거가
안 탄다**(판정 이름이 `weak_signal` 대신 `inconclusive` 가 될 뿐이다).

## 9. 안 하는 것 (YAGNI)

- **`_fold_key`·접기 계약**(§3).
- **`RESIDUAL_MIN_SCORE` 조정** - M4 는 아랫선이 옳은지를 묻지 않는다. 판정문이 최고
  점수를 수치로 실으므로 엔지니어가 "아깝게 몰랐다" 와 "흔적도 없다" 를 스스로 가른다.
- **E(서술·확신도 복수화)** - 사용 사례를 아직 못 잡았다(조사 §2.3).
- **통계 Minor 4건 · crude pooling · F.**

## 10. 성공 기준

실측 재현 3건이 뒤집힌다.

1. 잔차 2건 · loop=7 · 환각 지목 -> `inconclusive` 이면서 **`final_claims=2`**,
   판정문이 잔차를 언급한다.
2. 게이트 미경유(finalize 미호출) 종료 -> 백스톱이 잔차를 싣는다.
3. 전축 ok · 통과 0 · 비센서 후보 점수 전부 아랫선(RESIDUAL_MIN_SCORE) 미만 ->
   **`no_separation`**, 최고 점수가 판정문에 찍힌다. [Task 7 갱신: "잔차 0" 은
   Task 4 가 Critical 로 폐기한 옛 표현이다 - 표본이 얇아 미통과인 완전 분리
   후보는 `bundle.residuals()` 에도 안 잡혀 "잔차 0" 이 거짓 판정문을 낸다.]
4. 회귀 없음: 통과 후보가 있는 상태에서 `(4)` 가 싣는 목록은 **지금과 같다**.
5. 전축 no_signal(후보 0건) -> 여전히 `(2) no_signal` 이다.
