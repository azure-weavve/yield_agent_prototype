# 축 간 순위 공통 척도 설계 (2026-08-31)

`finalize` 계약 재정립의 **C 단계**. 선행 조사는 미추적 문서
`docs/2026-08-31-finalize-계약-영향범위.md` 에 있고, 이 설계는 그 조사가 권고한
착수 순서 **C → A → B → D/E** 의 첫 항목이다.

## 문제

순위는 축을 가로질러 후보를 줄 세우는 유일한 자인데, 지금 그 자가 **신호 세기가
아니라 참조집합 크기를 잰다.**

`graph/evidence.py:_rank_key` 는 `(p_permutation, -score)` 다. 그런데 순열 p 는
`p = (초과횟수 + 1) / (참조회차 + 1)` 이고 바닥은 `1 / (참조회차 + 1)` 인데,
2026-08-29 에 귀무 참조집합을 **표본 크기가 같은 회차**로 좁히면서
(`tools/commonality.py::_null_distribution`) **참조 회차가 후보마다 달라졌다.**
그래서 이런 일이 벌어진다.

| 후보 | p | 바닥 | 실제 |
|---|---|---|---|
| X | 0.111 | 0.111 | 완전 분리. 참조가 8회뿐이라 더 못 내려간다 |
| Y | 0.050 | 0.003 | 약한 신호. 참조가 300회라 더 내려갈 수 있었는데 안 내려갔다 |

현재 규칙은 Y 를 1등으로 놓고, X 를 지목한 LLM 을 반려한다. **X 는 자기 표본이 낼
수 있는 최강을 냈는데 진다.**

여기에 두 번째 문제가 겹친다. 앞으로 들어올 증거(2단 센서, 등록 패턴으로 설명되지
않는 잔차)는 순열 p 를 내지 않는다. 지금 규칙은 p 가 없으면 1.0 으로 밀어 **자동
꼴찌**로 만들고, 게이트 (1)번은 "1등 묶음" 을 요구하므로 그 증거는 영원히 승인되지
않는다. C 를 A·B 보다 먼저 하는 이유가 이것이다.

## 결정 요약

| 항목 | 결정 |
|---|---|
| 근본 방침 | **갈리지 않으면 동점.** 전순서를 억지로 만들지 않는다 |
| 비교 단위 | 두 후보가 **둘 다 표현할 수 있는 해상도**(= 거친 쪽 바닥)에서만 비교 |
| p 없는 증거 | **별도 등급으로 내린다.** 통계 등급 후보가 하나라도 있으면 그 아래 |
| 참조 0회(바닥 1.0) | 통계가 없는 것이므로 **비통계 등급**으로 내린다 |
| score tie-break | **같은 축 안에서만** 쓴다 (축을 가로지르면 안 되는 자다) |
| 순위 산출 | 지배당하지 않은 후보 전부 = 1등 층. 걷어내고 반복(층위 순위) |
| 게이트 승인 | `rank_key` 동일 비교 → **1등 층 멤버십** |
| 대표 선정·표시 순서 | 전순서 키를 그대로 쓴다 (우열 판정이 아니다) |

## 1. 규칙

### 1.1 등급 판정

```
통계 등급  <=>  p_permutation is not None  그리고  (p_min_possible or 1.0) < 1.0
```

바닥이 1.0 이라는 것은 참조 회차가 0 이라는 뜻이고, `_null_distribution` 의 주석이
못박아 두었듯 그것은 "우연이다" 가 아니라 **"비교할 귀무 표본이 하나도 없었다"** 다.
`hypotheses.yaml` 도 LLM 에게 그런 후보는 채택하지 말라고 이미 지시하고 있다.
통계가 실제로 없으므로 센서와 같은 등급으로 내린다.

`p` 는 있는데 `p_min_possible` 이 없는 조합은 도구가 둘을 같이 싣거나 같이 안 싣기
때문에(`domain/engine.py:evaluate`) 실제로는 생기지 않는다. 생기면 보수적으로
비통계 등급으로 떨어뜨린다.

### 1.2 지배 관계

```
a 가 b 를 지배한다  <=>

  [등급이 다르면]
      a 는 통계 등급이고 b 는 비통계 등급

  [둘 다 통계 등급이면]
      floor = max(a.p_min_possible, b.p_min_possible)     # 공통 해상도
      pa    = max(a.p, floor)                             # 바닥 아래는 표현 불가
      pb    = max(b.p, floor)
      pa < pb
      또는 (pa == pb 그리고 같은 축 그리고 a.score > b.score)

  [둘 다 비통계 등급이면]
      p 비교를 아예 건너뛴다 (없는 값이다)
      같은 축 그리고 a.score > b.score
```

**비통계 쌍에서 p 계산을 건너뛰는 것을 규칙으로 못박는다.** `p` 가 `None` 인 값을
`max` 에 넣으면 TypeError 이고, 1.0 으로 채워 넣으면 "참조 0회라 p 가 1.0" 인 후보와
"p 를 아예 안 낸" 후보가 같은 값이 되어 구분이 사라진다. 둘은 등급이 같으니 순위
결과는 어차피 같지만, 같은 값으로 뭉개 두면 나중에 등급 판정을 고칠 때 한쪽이
조용히 따라 움직인다.

여기서 나오는 귀결: **다른 축의 비통계 증거끼리는 항상 동점이다.** 그것이 사실이다 —
센서 효과크기와 잔차 크기를 같은 자에 올릴 방법이 지금 없다.

서두의 X·Y 를 넣어 보면 `floor = 0.111`, `pa = pb = 0.111` 이라 **동점**이다.
둘 다 1등 층이고 리포트에 둘 다 실린다.

### 1.3 왜 score tie-break 를 축 안으로 제한하는가

`score` 는 탐색 폭에 따라 부풀고 **그 부풀림 정도가 축마다 다르다.** 계측 축은
신호가 전혀 없는 데이터에서도 후보의 48.7%가 판별선을 넘는다(`hypotheses.yaml`
의 metro 항목에 실측이 적혀 있다). p 를 1순위로 둔 이유가 바로 그것인데, 현재
규칙은 tie-break 자리에서 그 자가 다시 축을 넘고 있다.

같은 `hypothesis_id` 안에서는 탐색 폭이 같으므로 score 비교가 성립한다. 그래서
거기서만 쓴다.

## 2. 층위 계산

```
남은 = 전체 묶음
층 = 1
남은 것이 있는 동안:
    앞줄 = 남은 것 중 남은 누구에게도 지배당하지 않는 것
    앞줄이 비면 앞줄 = 남은 것 전부            # 안전판 (아래 2.2)
    앞줄에 rank = 층 을 준다
    남은 -= 앞줄 ;  층 += 1
```

O(n²) 이고 후보 상한은 4축 x `COMMONALITY_TOP_K`(20) = 80 이라 비용은 무시할 수 있다.

### 2.1 비교 불가는 비이행적이지만 지배는 이행적이다

`X ~ Y`, `X ~ Z` 인데 `Z > Y` 인 상태가 정상적으로 생긴다(서두 표에 Z: p 0.002,
바닥 0.003 을 더하면 그렇다). 그래서 **비교자로 정렬할 수 없다.**

반면 지배 관계 자체는 이행적이다.

```
a > b 이면 max(pa, f_ab) < max(pb, f_ab) 이므로  pb > f_ab >= 바닥a, 바닥b  이고 pa < pb
b > c 이면 마찬가지로  pc > f_bc >= 바닥b, 바닥c  이고 pb < pc
=> pa < pb < pc 이고,  pc > pb > f_ab >= 바닥a  이며  pc > f_bc >= 바닥c
=> pc > max(바닥a, 바닥c) = f_ac
=> max(pa, f_ac) < pc = max(pc, f_ac)   즉  a > c
```

이행적이고 반대칭이므로 **엄격 부분순서**이고, 순환이 없어 층위 계산이 종료한다.

### 2.2 안전판을 그래도 두는 이유

위 증명은 등급이 같고 score tie-break 가 안 걸린 경우를 다룬다. 등급 조건과 축 내
score 조건이 섞였을 때까지 손으로 증명하지 않았으므로, 앞줄이 빈 경우 남은 전부를
한 층으로 내보내는 안전판을 두고 **그 안전판 자체를 테스트로 잠근다.** 안전판이
없으면 순환 한 번에 무한 루프다.

## 3. 버린 대안: 전역 양자화

"전 후보 바닥의 최댓값 하나로 p 를 절단" 하면 전순서가 나와 구현이 훨씬 간단하고
동점도 자연히 생긴다. 버린 이유는 **바닥이 큰 후보 하나가 전체 해상도를 망치기**
때문이다. 바닥 0.33 짜리가 하나 섞이면 p 0.001 과 p 0.30 이 같은 등수가 된다.
쌍마다 해상도를 잡으면 그 오염이 두 후보 사이에 갇힌다.

(참조 0회 후보를 비통계 등급으로 내리는 결정이 이 문제를 완화하기는 하지만
없애지는 못한다 — 바닥 0.33 은 참조 2회로 얼마든지 나온다.)

## 4. 코드 변경 지점

### 4.1 `graph/evidence.py`

- `_rank_key` 를 **`_order_key`** 로 이름을 바꾼다. 하는 일은 그대로(전순서)지만
  **우열 판정에서 손을 뗀다.** 남는 용처는 두 곳뿐이다.
  - `_sort_key` — 표시 순서 고정
  - `_fold_key` — 묶음 안 대표 선정 (우열이 아니라 "어느 이름으로 의뢰할 것인가")

  이 분리는 이미 이 파일이 배운 교훈이다. `_sort_key` 의 docstring 이 "우열을 묻는
  자리에 표시용 키가 섞이면 동점이라고 보고해 놓고 게이트는 반려한다" 를 기록하고
  있다. 이번에는 반대 방향으로 같은 실수를 막는 것이다.

- `ClaimGroup.rank_key` 프로퍼티를 **제거**한다. 전순서 키로 우열을 묻는 자리가
  남아 있으면 새 규칙이 조용히 우회된다. 이 제거가 닿는 곳은 전수 조사했다.

  | 위치 | 조치 |
  |---|---|
  | `evidence.py:87` 프로퍼티 정의 | 제거 |
  | `evidence.py:313` `groups_to_dicts` 등수 계산 | `layer_ranks` 로 |
  | `nodes.py:377` 게이트 (1) 승인 | 1등 층 멤버십으로 |
  | `nodes.py:619` 반려 "앞선 근거가 있다" | 1등 층 멤버십으로 |
  | `tests/test_evidence.py:358` | 동점 단언을 등수 동일로 다시 쓴다 |
  | `tests/test_multi_axis_dummy.py:328·341·343·357` | 아래 참조 |

  `test_rank_key_carries_no_display_tiebreak` 이 잠그는 계약("우열 키에 표시용
  tie-break 가 섞이면 안 된다")은 **여전히 유효하다.** 다만 그 계약이 이제 키가
  아니라 `dominates` 에 산다. 테스트를 지우지 말고 **`dominates` 가 `claim_id` 를
  보지 않는다**는 단언으로 옮긴다. `len(rank_key) == 2` 단언은 새 규칙에서 뜻이
  없으므로 버린다.

- 신설:
  - `_is_statistical(claim) -> bool`
  - `dominates(a: ClaimGroup, b: ClaimGroup) -> bool` (대표 claim 으로 판정)
  - `layer_ranks(groups) -> list[int]` — `groups` 와 같은 길이의 등수 목록

- `ranked_groups()` 는 층위 순서로 정렬해 반환한다(1차 = 층, 2차 = `sort_key`).
  표시 순서와 등수가 어긋나면 리포트에서 `[근거 2]` 가 `[근거 1]` 보다 위에 찍힌다.

- `groups_to_dicts()` 의 등수 계산(연속한 `rank_key` 비교)을 `layer_ranks` 호출로
  바꾼다. `tied` 는 같은 등수의 개수로 세는 현행 방식을 유지한다.

### 4.2 `graph/nodes.py`

- `_finalize_gate` (1) 승인 조건:
  `picked.rank_key == groups[0].rank_key` → **`picked` 의 층위 등수가 1**.
  `find_group` 이 목록에서 꺼낸 **바로 그 객체**를 돌려주므로 위치를 `is` 로 찾는다
  (그 함수의 docstring 이 경고하는 함정이다 — 매번 새로 만들면 조용히 어긋난다).
- `_gate_rejection` 의 "앞선 근거가 있다" 분기도 같은 판정으로 바꾼다. 문구도
  고쳐야 한다: 지금은 p 와 점수 두 숫자만 인용하는데, 새 규칙에서 지는 이유는
  **"공통 해상도에서 졌다"** 이므로 바닥을 함께 대야 LLM 이 반려를 이해한다.

### 4.3 리포트 문구 — `evidence.format_group_line`

동점 줄이 지금 이유를 못박고 있다.

> "같은 등수의 근거가 더 있다 - **순열 p 와 분리 점수가 같아** 어느 쪽이 유력한지
> 현재 증거로는 정할 수 없다"

새 규칙에서 이것은 **틀린 이유**다. p 가 0.111 과 0.050 으로 달라도 동점이 된다.
"이 표본들이 낼 수 있는 해상도(바닥 X)에서는 갈리지 않는다" 로 바꾼다.

### 4.4 `domain/hypotheses.yaml` (4곳)

yaml 은 코드가 아니라 **LLM 이 읽는 계약 문서**다. 순위 규칙이 바뀌면 게이트 반려
문구가 바뀌는데, LLM 이 그 반려를 이해하려면 규칙을 미리 읽고 있어야 한다.
4개 가설 전부에 다음을 명시한다.

- p 가 자기 바닥에 걸린 후보는 **더 작은 p 를 가진 후보에게 지지 않는다.**
- 순위는 두 후보가 **둘 다 표현할 수 있는 해상도**에서 매겨진다.
- 참조 0회(바닥 1.0) 후보는 통계 근거가 없는 것으로 취급되어 뒤로 밀린다.

(통계 해석 문단이 4가설에 복붙돼 있다. 지난 순열 p 교정 때 리뷰 Important 4건 중
2건이 바로 이 yaml 계약 구멍이었으므로 4곳을 반드시 같이 고친다.)

`graph/nodes.py:ANALYZE_SYSTEM_PROMPT` 의 "순위 1등이 아닌 것을 지목하면 반려된다"
는 그대로 참이다. 손대지 않는다.

### 4.5 낡아지는 주석 3곳

`_rank_key` 를 **"축을 가로지르는 유일한 자"** 로 부르는 서술이 도구 쪽 모듈에
퍼져 있다. 이름이 바뀌고 읽는 법도 바뀌므로 같이 고친다. 안 고치면 다음 사람이
없는 함수를 찾는다.

- `tools/commonality.py:436`
- `tools/metro_commonality.py:107`
- `tests/test_metro_commonality.py:657` (주석)

고친 뒤의 서술: p 는 여전히 축을 가로지르는 유일한 자이되, **자기 바닥과 함께
읽어야** 하고 비교는 두 후보의 공통 해상도에서 이뤄진다.

## 5. 비통계 등급은 이번에 비어 있다

센서 결과(`tools/sensor_compare.py`)는 `hypothesis_id` 를 안 실어서 아직 Claim 이
되지 못한다(`graph/evidence.py:409 _is_hypothesis_result`). 그 문을 여는 것은 A
작업이다. 따라서 이번에 만드는 비통계 등급은 **합성 Claim 으로만 테스트되고,
실경로에서는 비어 있다.**

그것이 결함이 아니라 순서의 이유다. 규칙을 먼저 정하지 않고 A 를 하면, 새로 들어온
증거가 전부 자동 꼴찌가 되어 아무 데도 안 나온다.

## 6. 테스트

**규칙 (evidence 층, 합성 Claim)**

1. 바닥이 다른 두 후보가 공통 해상도에서 안 갈리면 동점이다 (서두 X·Y).
2. 공통 해상도에서 갈리면 진다 (Y·Z).
3. 비교 불가가 비이행적인 배치에서 층위가 정상 산출된다 (X·Y·Z 동시).
4. 통계 등급이 비통계 등급을 항상 지배한다.
5. 통계 후보가 0건이면 비통계 증거가 1등 층이 된다.
6. 바닥 1.0(참조 0회) 후보는 비통계 등급으로 내려간다.
7. score tie-break 는 같은 축에서만 걸린다 — 다른 축이면 p 가 같을 때 동점.
8. 순환 안전판: 지배 관계를 강제로 순환시킨 입력에서 종료하고 한 층을 낸다.

**게이트 (`graph/nodes.py`)**

9. 1등 층에 있는 후보를 지목하면 승인된다 — 그것이 `groups[0]` 이 아니어도.
10. 1등 층 밖을 지목하면 반려되고, 반려 문구가 **바닥을 함께 인용**한다.

**회귀 확인**

기존 `finalize_status` 단언 33곳·`final_claims` 26곳(테스트 8파일)을 훑어, 깨지는
것이 **진짜 계약 변경 때문인지** 확인하고 그것만 갱신한다. 기준선은 422 passed.

`rank_key` 를 직접 단언하는 테스트 5곳(§4.1 표)은 **계약이 살아 있으므로 옮겨
쓰고, 지우지 않는다.** 테스트가 사라지면 새 규칙이 그 자리를 안 잠근 채로 남는다 —
지난 커밋에서 "새로 넣은 코드 3곳이 지워도 통과" 하던 것이 같은 종류의 구멍이었다.

**훼손 실험 (필수)**

리뷰가 5회 연속 실재 결함을 잡았고 그 절반이 "고치다 만든 회귀" 였다. 최소한
다음을 훼손해 테스트가 잡는지 확인한다.

- `dominates` 의 `floor` 를 `max` 대신 `min` 으로
- 등급 판정을 `< 1.0` 대신 `<= 1.0` 으로
- score tie-break 의 축 일치 조건 제거
- 층위 루프의 안전판 제거
- 게이트를 다시 `groups[0]` 대조로

**주의**: 훼손 루프가 도구 타임아웃에 죽어 훼손 파일이 다음 실행의 기준선이 된 적이
있다. 끝나면 `git diff` 로 워킹 트리를 확인한다.

## 7. 범위 밖

- **A (Claim 발급 자격 확대)** — 센서·잔차가 claim_id 를 받게 하는 것.
- **B (판별선의 이진 붕괴)** — `passes=False` 후보를 잔차로 싣는 것.
  `_record_evidence`·`_gate_rejection`·`_no_candidate_action` 세 곳이 `passing()`
  에 매달려 있다. 이번에는 안 건드리되 훼손 대상에는 넣는다.
