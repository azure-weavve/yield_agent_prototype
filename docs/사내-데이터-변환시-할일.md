## 2. ETL 적재 스크립트 신규 개발 — `data/load_internal.py` (미작성, 핵심 작업)

현재 `data/` 엔 `generate_dummy.py` 만 존재. 사내 수율/공정 이력을 목표 스키마
(`yield`·`process_log` 2테이블)로 적재하는 스크립트를 새로 만든다.

- [ ] **`wafer → lot_id` 매핑 원천 확보 (필수)** — `wafer_id` 는 `{root_lot}_{no}` 라
  wafer_id 만으로 양산/평가 소속을 알 수 없음. 파생 불가, 매핑 데이터 별도 확보.
- [ ] **스키마 완화**: `spec_low` / `spec_high` 를 **NULL 허용**으로.
  (함수는 이미 NULL-safe. `generate_dummy.py` 의 `CREATE TABLE` 은 아직 `NOT NULL` —
  더미 전용이라 그대로 두고, 적재 스크립트가 nullable 스키마로 생성.)
- [ ] **신규 컬럼**: `root_lot_id`(품질 교차검증용), `lot_type`(양산=`.1` / 평가=그 외,
  **격리 함수로 구현** — 정확한 판정법은 보안상 이 저장소에 두지 않음).
- [ ] EDS `/search` 응답의 wafer 식별자도 `{root_lot}_{no}` 체계인지 확인
  (다르면 `HttpEDSSearcher` 매핑에서 조립).
- [ ] 적재 후 정합성 검사: `validate_data_completeness` 스모크, `find_low_yield_lots`
  직접 호출로 상식 검증.

## 3. 실데이터가 들어와야 드러나는 코드 수정 (아직 미구현)

- [ ] **`find_low_yield_lots` 에 lot_type 필터** (`tools/yield_tools.py`) —
  평가랏은 의도적 저수율이 정상이라 이상 lot 오탐의 주범. `lot_type` 컬럼이 생긴 뒤
  양산랏만 대상(또는 별도 임계). (`internal-data-integration.md` 3-2)
- [ ] **`HttpEDSSearcher` 응답 스키마 실측 매핑** (`tools/eds_search.py`) —
  필드명 `wafer_id`/`score` 가 추정값. 사내 실제 응답으로 확정 + 오류 응답(4xx/5xx,
  타임아웃) 처리 방침 결정. (미룸 6번)
- [ ] **미룸 9번 크래시** (`tools/grouping.py` `normalize_target`) —
  yield DB 엔 있으나 EDS 인덱스엔 없는 wafer 를 한 장 입력하면
  `LocalEDSSearcher` 는 `KeyError`, `HttpEDSSearcher` 는 requests 예외로 그래프 통째로
  종료. 검색을 감싸 인덱스 미존재를 잡고 `unknown_target` 계열 조기 출구로 유도.

## 4. mock → openai 전환의 함의

- `ScriptedMockLLMClient` 는 더미 시나리오(aggregate → finalize(0.6) → compare →
  finalize(0.9))를 **하드코딩한 스크립트**. 실데이터에선 동작하지 않으므로
  **반드시 `LLM_MODE=openai` 필요**.
- 실제 LLM 은 mock 처럼 얌전하지 않다 — 엉뚱한 tool 이름·비숫자 confidence 를 낼 수 있음.
  이때 비로소 §0 의 tool 오류 복구·confidence 방어(이미 구현됨)가 실효를 발휘한다.
- 그 밖의 실패 경로 테스트 확충(미룸 7번)과 finalize 승인 후 후속 tool 중단
  (미룸 5번, C-1 — 현재 "다음 작업")도 이 단계에서 함께.
