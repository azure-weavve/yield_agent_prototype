## 0. 한 줄 결론

**F 의 입장료는 "서브에이전트가 부른 도구를 `findings` 에 원래 모양 그대로 병합하는
것" 하나이고, 그 모양이 생각보다 빡빡하다.** 레코드 스키마는 대부분 이미 있다 —
빠진 것은 **분포 형태**와 **해석 노트 채널** 둘뿐이다.

## 1. 감사 기록(`findings`)이 지금 무엇을 떠받치는가

`graph/state.py:19` — `findings: Annotated[list[dict], operator.add]`. 덮어쓰기가 아니라
**누적**이고, 소비자가 넷이다.

| 소비자 | 자리 | 무엇을 읽나 |
|---|---|---|
| 증거/claim 전체 | `evidence.build_bundle(findings)` (`graph/evidence.py:671`) | `result` 가 dict 이고 `hypothesis_id`+`candidates` 면 claim 으로 투영 |
| 커버리지 | `graph/nodes.py:865 _coverage` | `ran`(유효 결과) · `failed`(실패 표식) · `no_data`(status) — **등록 축(`hyp_*`)으로 한정** |
| 리포트 LLM | `graph/nodes.py:1122` → `llm/client.py:514` | `findings` 를 **JSON 그대로** 넘기고 "수치를 그대로 인용하라" 고 지시 |
| 콘솔 감사 출력 | `main.py:32` | 실행 순서대로 사람이 읽는다 |

**즉 `findings` 는 이 시스템의 유일한 진실이다.** 서브에이전트 안에서 부른 도구가
여기 안 남으면: claim 0개 → 게이트 승인 불가 · 커버리지가 "안 돌린 축" 으로 보고 ·
리포트 LLM 이 근거 없이 서술.

### 레코드 계약 (tools_node 가 지금 만드는 모양)

```python
{"loop": int, "tool": str, "args": dict, "result": Any, "thought": str}
# 선택: "failed": True   (복구 불가능한 실패에만)
# 리포트 직전 추가: "superseded": True   (같은 축 재실행에 밀려난 실행)
```

**`args` 는 "LLM 이 보낸 인자" 가 아니라 "실제로 실행된 인자" 다**(`nodes.py:229` 주석).
`group_ids`/`control_ids` 가 주입된 뒤의 값이어야 하며, 아니면 감사 기록이 실행과 다른
분모를 가리키고 그것이 리포트의 근거 문장이 된다.

## 2. F 에서 깨지는 자리 6개 (전부 대응이 필요하다)

1. **주입 우회.** 워커가 도구를 직접 부르면 `_with_pipeline_groups`(`nodes.py:248`)를
   안 타서 대조 분모가 LLM 손에 돌아간다. → 워커의 도구 실행은 **tools_node 와 같은
   경로**를 쓰거나 그 함수를 공유해야 한다. (이게 제일 조용히 깨지는 자리다.)
2. **실패 분류.** `failed` 표식은 `_tool_error_message`(`nodes.py:292`)가 "복구 가능한
   인자 오류인가" 를 가른 결과다. 워커가 자체 try/except 로 잡으면 **멀쩡한 축이
   영구히 타거나**, 반대로 터진 축이 '안 돌린 축' 과 섞인다.
3. **`loop` 번호 충돌.** 워커마다 자기 루프 카운터가 생긴다. 게이트의 루프 한계
   판정과 리포트의 순서 표시가 이 값을 쓰므로 병합 규칙을 정해야 한다
   (후보: `loop` 은 메인 진행도로 두고 워커 내부 회차는 별도 키).
4. **대체(superseded) 위치.** `build_bundle` 은 **findings 의 순서(위치 i)** 로 같은 축
   재실행을 판정한다. 워커가 축 안에서 같은 도구를 여러 번 부르면 그 순서가 병합 뒤에도
   보존돼야 한다.
5. **센서 결과의 특수 취급.** `kind: sensor` 는 `ran`/`statuses`/폐기 장부에 안 들어간다
   (`evidence.py:697` 이하). 분포 축 워커가 센서를 부르므로 이 성질이 병합 후에도
   유지되는지 테스트가 필요하다.
6. **커버리지 어휘.** `_coverage` 는 `TOOLS_BY_NAME` 의 `hyp_*` 를 등록 축으로 센다.
   워커를 축 단위로 묶어도 **커버리지 단위는 여전히 도구**여야 한다(축 단위로 바꾸면
   지금까지의 판정 계약 4개가 같이 움직인다).

## 4. 방식 B 레코드 스키마 — 이미 있는 것과 없는 것

| 설계가 요구한 필드 | 현재 | 자리 |
|---|---|---|
| 축 / grain | ✅ | `hypothesis_id` + `level` |
| 대상 식별자 | ✅ | `key` + `level_columns` |
| **영향 wafer 집합** | ✅ | `target_wafers` / `control_wafers` |
| 대조 구조 | ✅ | `target_pass/total` · `control_pass/total` · `n_strata` · `strata` |
| 효과 크기(축 무관 공통 척도) | ✅ | 축 간은 `p_permutation` + `p_min_possible`(공통 해상도), 점수는 **축 내부 전용** |
| 커버리지·신뢰도 | ✅ | `coverage_*` · `n_reference` · `p_at_floor` · `meta.missing_*` |
| 기존 가설 매칭 / 미설명 잔차 | 🔸 부분 | `residuals()` + `weak_signal` 은 있으나, **축 안에서 "이름 없는 이상" 을 새로 발견하는 기능은 없다** |
| **분포 형태**(시프트/분산확대/이봉) | ❌ | metro 는 `split_value`/`split_direction` 뿐, 센서는 `target_std`/`control_std` 원자료만(분류는 없다) |
| **해석 노트 채널** | ❌ | Claim 에 자유 텍스트 자리가 없다. 지금 서술은 리포트 LLM 이 한 번에 만든다 |

→ **F 가 진짜로 새로 만들어야 하는 것은 이 두 줄이다.** 나머지는 워커가 채워 넣을
자리가 이미 있다("계약을 채우는 실행 껍데기").

⚠️ 노트 채널을 열 때 주의: 자유 텍스트가 게이트 판정에 닿으면 "LLM 제안, 코드 결정"
이 깨진다. 설계 문서의 절충안대로 **레코드(구속력) / 노트(리포트 서술 전용)** 를
분리하고, 노트는 `findings` 에 남기되 `Claim` 으로는 투영하지 않는 쪽이 안전하다.

## 5. 오독 측정 설계 (사내 접근 열리면 바로 돌릴 것)

**F 의 유일하게 남은 미검증 이득 = 축 전용 프롬프트가 오독을 줄이는가.** 그래프를 안
돌리고 프롬프트만 두 번 때린다.

- 입력: 같은 도구 결과 JSON 세트(더미 DB 에서 미리 뽑아 고정)
- (a) 현재 4축 통합 프롬프트 (b) 축 전용 프롬프트
- **오독 5종을 센다**: ① `score` 만 보고 채택 ② `target_total` 을 그룹 크기로 읽음
  ③ `key` 문자열 파싱 ④ p 편향/바닥값 무시 ⑤ `fdr_table` 무시
- 판정: (b)가 (a)보다 의미 있게 적으면 F 착수. 차이가 없으면 **"코드 축 묶음"**
  (축별 페이즈를 코드가 강제, LLM 호출 증가 0)으로 충분하다.

⚠️ mock 으로 재면 의미가 없다(mock 은 오독을 안 한다). **사내 모델이 필요하다.**

## 6. 사내에 확인할 것 (답 하나에 설계가 갈린다)

1. **게이트웨이가 동시 호출을 허용하는가, 한도는?** — 지금 "순차 확정" 의 근거였던
   Msg-Id 충돌은 **클라이언트를 하나만 만들어 쓰는 현재 구현**의 산물이다
   (`llm/client.py:428-437`: 두 Msg-Id 가 클라이언트당 한 번 생성돼 모든 요청이 같은
   값을 단다). 워커마다 클라이언트를 따로 만들면 각자 새 값을 달므로 충돌은 사라진다.
   → 허용된다면 병렬이 열리고, 실데이터에서 축 하나가 수십~수백 초인 것을 감안하면
   체감 시간 이득이 실재한다.
2. **호출 한도/예산** — 축 3개로 나누면 호출이 그만큼 는다.
3. (겸사) **Msg-Id 를 게이트웨이가 어떻게 쓰는가**(추적/중복제거) — 호출마다 새로
   만들어야 하는지 지금도 미확인이다(`client.py:429` 주석).
