# pooling 완료 후 다음 작업

기록: 2026-09-17. 사용자가 다음 순서를 확인했고, Claude가 pooling을 마친 뒤 다음 작업
진행 전에 알 수 있게 남기도록 요청했다. **현재 구현 완료를 뜻하는 문서가 아니다.**

## 확정된 다음 작업

**후속 질문·데이터 추천 기능을 실제로 구현한다.**

설계: [후속 질문·데이터 추천](2026-09-17-후속질문-데이터추천-설계.md).
관련 방향: [F 멀티에이전트 설계](2026-09-17-F-설계정리.md).

## 진행 순서

1. `pooling-mh-score`의 구현·필수 검증·리뷰 완료를 확인하고 최종 코드와 변경 범위를 기록한다.
   진행 중 pooling과 같은 코드·테스트를 동시에 수정하지 않는다. 커밋/푸시는 기존 사용자 결정에 따른다.
2. 최종 코드와 위 설계를 대조하고 `docs/tasks/<task>/plan.md`를 작성한다.
   구현 단계별 owner, 인터페이스, 리뷰 기준선과 사전 변경, 완료 기준을 명시한다.
3. **코드 기반 추천 생성과 검증부터 구현한다.** 첫 범위는 교락을 가르는 질문, 표본 미달,
   데이터 누락·실패, 미실행 축 추천이다. 출처와 도구 실행 가능성·데이터 확보 여부를 구분한다.
4. 리포트에 `[후속 질문·필요 데이터]` 블록을 연결한다. 기존 판정·근거·그룹·coverage를
   바꾸지 않고 추천 생성 실패에도 기존 결과를 보존한다. 추천된 도구를 자동 실행하지 않는다.
5. 설계의 해당 Q1~Q12와 회귀 테스트를 수행하고, 저장소 지침에 따른 구현·독립 리뷰를 완료한다.
6. 이후 LLM 질문 구체화와 멀티에이전트 연결을 진행한다. F 구현은 공통 실행기 → 경로 워커
   1개 → 나머지 워커 순으로 간다.

## 이미 정해진 사항

- 멀티에이전트 구축은 사용자 목표다. 필요성 입증이나 단일 에이전트 대비 비용 우위를 다시
  착수 조건으로 세우지 않는다. 사내 API 사용량 제약은 크지 않다.
- 사내 오독 평가는 품질 개선용이다. 로컬 추천 구현을 그 평가 전까지 미루지 않는다.
- 질문·데이터 추천은 현재 설계 문서만 작성된 상태다. 구현돼 있다고 간주하지 않는다.
- 새 조건부 통계 도구·metro pooling·자동 타깃 변경은 이 첫 구현 범위가 아니다.
- 이 메모는 다음 작업 순서의 인계이며 현재 pooling 계획이나 workflow 실행 상태를 변경하지 않는다.

다음 작업이 실제로 시작되면 이 문서에 해당 plan 경로와 상태를 추가해 중복 착수를 방지한다.
