# pooling-mh-score — 분리 점수를 층별 가중(Mantel-Haenszel)으로 바꾼다

작성: 2026-09-16 · 설계자 Claude

## 목표와 요구사항

`tools/commonality.py` 가 **층(root_lot)별 2×2 를 합산한 뒤** 점수를 낸다. 층화는 순열
귀무에만 살아 있어 **p 는 lot 교락에서 보호되지만 점수는 보호되지 않는다.** 그 결과
심슨의 역설이 그대로 노출된다 — 2026-09-16 측정에서 **부호 뒤집힘을 재현**했다
(`docs/2026-09-16-pooling-전제-측정.md`).

점수는 `passes`(판별선) · 축 간 순위 · 잔차 아랫선 · `thin_sample` 판정이 **모두 얹혀 있는
뿌리 값**이다. 점수가 틀리면 그 위가 같이 틀린다.

요구사항:

1. `_score_map` 이 층별 차이의 **Mantel-Haenszel 가중평균**을 낸다.
2. 관측과 귀무가 **같은 함수**를 타는 기존 계약을 유지한다.
3. 순열 루프의 비용을 늘리지 않는다(층별 리스트 할당 금지).
4. 층별 내역을 후보 데이터에 항상 싣고, 근거 줄에는 **갈릴 때만** 낸다.
5. 이 변경으로 거짓이 되는 LLM 계약 문장을 같이 고친다.

## 설계 결정과 이유

### D1. 추정량 = MH 위험차 가중

층 `i` 마다 `d_i = a_i/nt_i - c_i/nc_i`, 가중치 `w_i = nt_i·nc_i/(nt_i+nc_i)`,
점수 `= Σ w_i·d_i / Σ w_i`.

- 층 건너뛰기 규칙은 **지금 그대로** 둔다(`nt_i == 0` 이나 `nc_i == 0` 이면 대비할 짝이 없다).
- **층이 1개면 옛 값과 정확히 동일**하다 → 자동 선정 경로(타깃 1장)는 회귀가 없다.
- **층 모양(비율)이 같아도 동일**하다 — 2026-09-16 실측에서 두 층을 3/17 로 맞췄더니
  후보 18개가 전부 차이 0.000 이었다. 즉 이 변경이 값을 바꾸는 것은 **층 모양이 다를 때뿐**이다.

### D2. 순열 루프에 할당을 안 붙인다

`_aggregate` 는 **순열 회차마다** 돈다. 층별 내역을 리스트로 모으면 그 비용이 귀무 전체에
곱해진다 — 전례가 있다(`collect_bits` 를 켜고 돌렸더니 **+22%**, 2026-08-23 실측).

그래서 층 루프 안에서 **누적자 두 개(`num`, `den`)만** 갱신한다. pooled `a/b/c/d` 는
표본 수 표시에 필요하므로 그대로 유지한다. 층별 상세는 **`collect_bits` 와 똑같은 모양으로
관측 경로에서만** 모은다(귀무는 점수만 읽고 버린다).

⚠️ `_aggregate` 독스트링이 이미 경고한다 — *"이 플래그가 a/b/c/d 나 stratum 스킵에 영향을
주게 만들면 안 된다"*. 새 누적자도 같은 규칙을 따른다: **출력 플래그가 점수에 영향을 주면 안 된다.**

### D3. 절단과 귀무 계약은 그대로

`_score_map` 의 `s > MIN_SCORE` 는 그대로다. 이제 `s` 가 MH 값이고, 귀무도 같은 함수를
타므로 **관측과 귀무에 같은 절단**이 걸린다는 기존 계약(설계 §1-4)이 유지된다.

### D4. 출력 — 구조로는 항상, 줄은 갈릴 때만 (사용자 결정)

- 후보 데이터에 `strata_detail`(층별 `root_lot_id`·`nt`·`a`·`nc`·`c`·`d`)을 **항상** 싣는다.
  → LLM 프롬프트와 감사 기록에 남는다.
- 근거 줄: 층이 2개 이상이면 점수 뒤에 **`(층 N개 가중)`** 을 붙인다. 검산이 안 맞는
  이유가 줄 안에 있어야 한다.
- 층별 내역 줄은 **갈릴 때만** 붙인다. "갈린다" 의 정의는 임의 상수가 아니다:
  **①`score` 와 `score_pooled` 가 판별선(0.5)·잔차 아랫선(0.25) 구간을 서로 다르게
  가로지르거나 ②부호가 다를 때.** 둘 다 이미 계약에 있는 선이다.
- `score_pooled` 도 함께 싣는다 — **설명용이지 판정용이 아니다.** 어떤 판정 코드도 이 값을
  읽지 않는다(단언으로 잠근다).

### D5. 임계와 참조집합은 안 건드린다

판별선·아랫선은 별개 노브다. 층 1개·같은 모양에서 값이 안 변하므로 지금 조정할 근거가 없다.
`_size_map` 의 조건화도 pooled `nt` 그대로 두되, **"이 조건화는 pooled nt 다"** 를 독스트링에
명시한다(다음 사람이 "추정량만 층화하고 조건화는 왜 pooled 인가" 로 돌아오는 자리다).

### D6. 함께 고쳐야 참이 되는 자리

1. **`llm/client.py` 근거 JSON 설명** — 지금은 "수치를 그대로 인용하라" 뿐이라 LLM 이
   합산 카운트로 점수를 재계산해 **다른 숫자**를 쓸 수 있다. *"score 는 층(root_lot)별
   가중 평균이다. `target_pass/target_total` 로 score 를 다시 계산하지 마라"* 를 넣는다.
2. **`domain/engine.py`** 화이트리스트 — `n_strata`·`score_pooled`·`strata_detail` 을
   넘기지 않으면 게이트·리포트가 그 값을 **아예 못 본다**(`n_strata` 가 지금 그 상태다).
3. **`_score_map` 독스트링** — "합계로 낸다" 는 서술이 거짓이 된다.
4. **`metro_commonality.py`** — 같은 결함이 남아 있다는 사실을 주석으로 박는다(별건).

### R-B1. 누적을 **정확 산술**로 한다 (blocking)

`mh_num`/`mh_den` 을 float 로 누적해서 **같은 유리수가 회차마다 다른 double 이 된다.**
결과가 값의 오차에 그치지 않는다:

- **순열 p 가 비보수적으로 틀린다.** `_null_distribution` 의 `>= obs` 가 동점을 세는데,
  참조집합은 pooled `nt` 만 맞추므로(`_size_map`, 의도된 설계) 층 모양이 회차마다 달라
  동점이 조용히 "못 넘음" 으로 떨어진다. 2층 배치 90개 전수 실측에서 **19개 배치의 p 가
  틀렸다**(예: 0.0125 로 보고되나 정확 산술은 0.0393). **HEAD 의 옛 코드에서는 동점 손실
  0건** - 이 변경이 들여온 회귀다. ⚠️ 2026-08-28 실측이 참조집합을 **보수적** 쪽으로
  좁혀 둔 것인데 이 회귀는 그 방향을 거꾸로 민다.
- **참값 0 이 절단을 통과한다**(리뷰 M-a). 층 간 상쇄가 `+1.1e-16` 으로 남아 `s > 0.0` 을
  넘는다. `nt_i,nc_i >= 2` 로 제한해도 2층 조합 **7,572개**가 이 상태이고, end-to-end 에서
  `status: no_signal` 이 `ok` 로 뒤집히는 것을 확인했다 → `(2) no_signal` 판정이
  `(2b) no_separation` 으로 바뀐다.
- **"층 1개면 옛 값과 정확히 동일" 이 거짓이 된다**(리뷰 m1). `(w·d)/w != d`. `nt,nc <= 120`
  전수에서 `round(·,3)` 이 달라지는 경우 **7,048건**(판별선·아랫선을 가로지르는 것은 0건).

**D1 의 추정량 정의와 가중치는 바뀌지 않는다.** `w_i·d_i = (a_i·nc_i − c_i·nt_i)/(nt_i+nc_i)`
는 대수적 동치이고, 이것을 정수쌍(또는 유리수)으로 누적해 **마지막에 한 번만 나눈다.**
구현 형태(정수쌍 누적 vs `Fraction`)는 **구현자 자율**이되, 아래 둘을 만족해야 한다.

- 수학적으로 같은 값은 **같은 double** 이 된다(동점이 동점으로 남는다).
- 층당 나눗셈이 줄어 R-M-b 의 성능 초과분이 함께 완화되는지 **실측으로 확인한다.**

⚠️ **정정(2026-09-20 재리뷰 RR-M1, 2026-09-21 3차 리뷰 TR-M3 가 재확인)** — 위
문장은 거짓이었다. 정수 정확 산술(R-B1)을 거쳐도 `(a·nc-c·nt)/(nt·nc)` 는
`fl(a/nt) - fl(c/nc)` 와 **다른 double** 이다(`nt,nc<=79` 전수의 51%가 다른
double, `round(.,3)` 기준으로도 5,528건이 갈린다). 옛 값과 비트 단위로 같게
만드는 float 분기(RR-M4)는 동점 손실 때문에 되돌렸다. 참인 것은 "대수적으로
(실수값으로) 같다" 까지이고, T1 이 잠그는 `ch["score_pooled"] == ch["score"]
== 0.417` 은 성질이 아니라 그 픽스처(2/3, 1/4)의 우연이다 — RR-M1 절과
아래를 참고할 것.

- 구현 형태는 자율이되 **D1 정의·절단·조건화는 여전히 금지 대상**이다. 최적화가 값을

- 최적화 뒤 **같은 방법으로 재측정**하고 수치를 보고한다. 그래도 남는 초과분의 수용 여부는

### RR-B1. LLM 프롬프트 판별자 문장이 payload 와 어긋난다 (blocking)

emit 조건(`llm/client.py:612`)은 `score_pooled is not None` 으로 맞다. 그러나 LLM 이 읽는

**engine 이 만든 모양 그대로의 metro claim 을 섞은 혼합 리스트** 단언을 넣는다. 기존
`test_operational_client_prompt_does_not_mislabel_metro_and_sensor_claims` 의 픽스처는
키 자체가 없는 손수 만든 모양이라 운영 경로를 안 탄다.

### RR-M1. "층 1개면 옛 값과 정확히 동일" 은 **여전히 거짓**이다 (major)

단일 stratum 에서 옛 값은 `fl(fl(a/nt) - fl(c/nc))`, 새 값은 `fl((a·nc - c·nt)/(nt·nc))` 라
double 이 다르다. `nt,nc <= 79` 전수의 **51%**, `round(·,3)` 차이 **36,156건**(1차 리뷰가 float
버전에서 센 7,048건보다 많다).

**단, `round(·,3)` 기준 판별선(0.5)·아랫선(0.25) 구간은 `nt,nc <= 120` 전수에서 0건 변화다 —
게이트·잔차 판정은 무사하고 영향은 표시값과 동점 판정뿐이다.**

→ R-B1 의 "m1 을 구현으로 닫았다"(이 문서 247-248)는 **거짓 기록이므로 정정한다.**

### 이 작업에서 남긴 교훈

- **"리뷰어가 새로 찾은 게 0건" 은 완료 기준이 될 수 없다.** 탐색 공간이 열려 있으면 발산한다
  (새 훼손 SURVIVED 3 -> 8 -> 18). 완료 기준은 **닫힌 목록**으로 세운다.
- **"X 는 판정에 안 쓴다" 류는 자리별 잠금이 아니라 불변 단언으로.** X 만 흔들고 출력 전체가
  같은지 본다 - 새 자리가 생겨도 자동으로 잡힌다.
- **불변 단언은 공허해지기 쉽다.** 픽스처가 그 경로를 실제로 움직이는 모양(동점·경계·스킵
  조건)이어야 한다. 이번 라운드에서 Sonnet 이 한 건, Claude main 이 두 건을 잡았다.
- **구현과 훼손 검증을 분리한다.** 서브에이전트가 디스크 훼손 도중 중단되면 잔재가 남을 수
  있고(2026-09-21 실제로 한 번 중단됐다), 보고서를 믿을 필요도 없어진다.
